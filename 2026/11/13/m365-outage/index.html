《Exchange 打不开了》

2026-11-13阅读 … 次

北京时间十一月十三号凌晨两点不到，Microsoft 365 出了问题。那时候美国东部是十二号中午快一点，苏州这边是半夜。

先出问题的是 Exchange Online，也就是 Outlook 背后的那些邮箱。微软一开始说美洲的用户连不上邮箱，后来又说 Teams、SharePoint、Copilot、Defender XDR 也可能受影响。

北京时间两点半前不久，Downdetector 上关于 Outlook 的报告有十三万多条，Microsoft 365 有四万六千多条，Teams 三千来条。到三点零七分，Outlook 的报告还有九万七千多条。这些是用户自己在网站上提交的，路透社也提醒，实际受影响的人数可能不是这个数。

这张图画的就是这样一夜。屏幕是红的，上面写着 Investigating，下面一行小字说正在尽快恢复服务。杯子上写着 IT Admin，咖啡还冒着热气。窗外在下雨，那个人趴在桌上，眼睛还睁着。玻璃上有一行字：Hello darkness, my old friend.

微软一开始说，好几个区域的基础设施负载升高了。

听上去像是人太多，挤不进去。后来它说，总的流量并没有涨，是一批服务器意外不能用了，剩下的服务器负担就重了。好比一个车间，来干活的人一个没少，机器停了一批，剩下的机器就得多干。

这些服务器没通过自动健康检查。健康检查是看一台服务器还能不能接活，检查不过，就不让它接活了。微软说已经想办法不让更多服务器受影响，同时让出问题的服务器恢复服务。

北京时间四点前，微软说在试一个办法，绕开处理健康检查的那个组件，同时在查这些服务器的处理器占用为什么偏高。

五点，它说换了一种健康检查的办法，一部分服务器回来了，正在铺开，还在准备自动恢复，发现哪台服务器不响应就去重启它。

早上八点不到，Exchange Online 又更新了一次：有些已经恢复的服务器，流量一回来，又不响应了。微软在限制一部分流量，还在试用旧版软件配置重新搭起来的服务器。

到上午十点左右的报道里，微软说重启服务器以后情况有些好转，但还要看稳不稳。它又说，有一个负责建立安全连接的进程被压垮了，服务器因此不再处理请求。最近有一项网络配置变更，恰好是在故障开始的时候做的，微软开始回滚这项变更。时间碰在一起，不等于就是它，回滚有没有用，微软自己也还在看。

那次更新的时候，Exchange Online 的事件 EX1550543 和 Microsoft 365 的事件 MO1550821 在服务健康面板上都还开着。到我写这篇的下午两点多，还没看到微软宣布完全恢复，根本原因也没有公布。有人问是不是被攻击了，微软没有披露任何被攻击的证据。

出问题的不只是 Outlook 客户端。Outlook 网页版、MAPI、Exchange ActiveSync、REST API 都可能连不上，所以换个浏览器打开，也不一定有用。有些用 Outlook 桌面版和手机版收 Google 邮箱的人，也说访问出了问题。

可能跟着受影响的还有 Teams、SharePoint Online、Copilot、Defender XDR、Planner、To Do，还有 Purview 的几项服务。微软说，这些服务里要跟 Exchange Online 打交道的那部分功能会出问题，不跟它打交道的还能用。

这种时候，IT 管理员能做的事情不多。毛病不在谁的电脑上，在微软的服务器上，重启电脑、重装 Outlook，都解决不了。

他能做的，是打开管理中心，盯着那两个编号，一遍一遍地刷新。然后回答同一个问题：

“邮箱是不是坏了？”

“是。”

“什么时候好？”

“微软说在处理。”

图上那个人大概就是这么过来的。

图上那句歌词管它叫老朋友。这两个月 Microsoft 365 也确实来过几回：九月十六号，美国有些用户可能打不开 Microsoft 365；十月五号到六号，有些管理员可能进不去管理中心；十月十三号，德国那边通过 Global Secure Access 用 Microsoft 365 的人，Outlook、Teams、OneDrive 断了将近十一个小时。不过那几回都只碰到一部分人、一部分功能，没有这回这么大。

这回到底是哪里坏了，要等微软正式说。
